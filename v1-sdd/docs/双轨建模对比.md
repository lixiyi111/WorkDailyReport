# 双轨建模对比（300 字）

UML 图适合表达结构与关系：用例图能一眼看清角色和功能边界，类图、ER 图把实体、属性和约束固定下来，泳道图能展示跨角色的流程；它直观、便于评审，但写不下验收标准和文字约定。Markdown 规范适合表达文字性约定：目标、范围、接口字段、错误码、验收标准、ADR 都能逐条写清、版本控制和追溯，但不如图直观。

在本项目中，`proposal.md` 用文字定范围和成功标准，`design.md` 用文字写模块职责、接口契约和非功能约束，UML 作为附件补结构与流程；两边用 S 编号、IR 编号互相引用——用例图里的每个用例能追溯到 proposal 的 S 编号，ER 图的每张表能在 design.md 找到字段说明，泳道图的每一步对应 tasks.md 的一个任务。图看全局，文定细节，配合使用才完整。
