## 3. 环境与运行

- Python：`conda activate work_daily`（Python 3.12），**不要用 base 的 3.9**；
- MySQL：`127.0.0.1:3305`，库 `daily_report_v2`，字符集 `utf8mb4`；
- Node.js：20+；
- 后端：`uvicorn app.main:app --reload --port 8000`；
- 前端：`npm run dev`（默认 5173）。

## 4. 本阶段工作流

1. **writing-plans**：把 v1 的设计结论转成 v2 的任务清单（`04-v2-tasks.md`），每条任务含交付物、验收标准、依赖、并行组；
2. **executing-plans / TDD**：逐任务执行——先写失败测试（红）→ 最小实现（绿）→ 重构；
3. **systematic-debugging**：出现缺陷时先复现、定位最小根因，再修复并补回归测试；禁止「改到能跑为止」；
4. **code-review**：每个任务完成前评审 diff，意见逐条回应或修复；共享文件（主编排入口、`main.py`、路由聚合）串行修改；
5. **并行**：三个采集模块互不共享文件，可用子智能体并行；`orchestrator.py` 等共享文件必须串行。

## 5. 提交纪律

- 一次提交对应一个任务；
- 提交信息格式：`feat|fix|test|docs: [V2-xxx] 一句话说明`；
- 示例：`feat: [V2-010] 实现 GitHub 提交采集与幂等 upsert`；
- 每个任务完成后在 `04-v2-tasks.md` 勾选，并记录测试命令与结果；
- 不提交 `.env`、`node_modules/`、`__pycache__/`、数据库文件。

## 6. 完成定义（Definition of Done）

一个任务只有同时满足以下条件才算完成：

- [ ] 失败测试先于实现存在，并能说明它为什么失败；
- [ ] 实现后该测试通过，且相关回归测试通过；
- [ ] `ruff check .` 无告警；
- [ ] 验收标准逐条可验证；
- [ ] code-review 意见已回应或修复；
- [ ] 已按规范提交一次。
