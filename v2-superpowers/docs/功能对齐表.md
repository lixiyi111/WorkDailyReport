## 2. v1 的扩展页面与 v2 现状

| v1 页面 / 功能 | v2 现状 | 处理决定 |
|----------------|---------|----------|
| 工作台（今日记录、任务状态、最近运行、考勤） | 简化工作台（日报统计、最近日报、健康检查、数据源状态） | 保留简化版；详细统计留到后续 |
| 数据源配置（增删改、连接测试、手动采集） | 仅状态列表；生成走配置装配 | 课程 S1–S3 不要求配置 CRUD；暂不补 |
| 工作数据（提交 / 任务 / 消息明细） | 无独立页面；条目在日报详情可见 | v1 扩展；如答辩需要可加只读页 |
| 成员管理（增删改、停用） | 成员列表 API + 身份绑定页 | 课程 S4 只要求映射；CRUD 暂不补 |
| 系统设置 | 无 | v1 扩展；暂不补 |
| 运行日志（collection_runs） | `source_sync_state` + 推送记录 | 以同步状态替代；暂不补独立运行页 |
| 考勤（Mock 页面） | 无 | **第 4 周变更单**统一实现 |
| 可选增强（图表、PDF/Excel 等） | 无 | 不在本轮范围 |

## 3. 有意的差异

| 差异 | 原因 |
|------|------|
| v2 使用独立数据库 `daily_report_v2` | 不覆盖 v1 演示数据，便于两版对照 |
| v2 schema 重新生成并评审 | 课程要求从零实现，不复制 v1 代码 |
| v2 前端重新设计 | 只继承交互目标，不复制组件 |
| v2 认证密钥与默认密码独立 | 两套环境互不影响；部署前都要更换 |
| v2 GitHub 走真实采集 | 已同步 v1 的 `GITHUB_TOKEN` 与 `GITHUB_REPOS`；无 token 时才回退 Mock |

## 4. 结论

- **课程交付所需的核心功能已对齐**：采集 → 生成 → 推送 → 存储 → Web 查看/编辑 → 登录权限。
- **v1 的管理台扩展**（数据源 CRUD、工作数据页、成员 CRUD、设置、运行日志）不属于 proposal 的 S1–S9，v2 首轮不逐页复刻；若第 4 周时间允许，可按 `V2-064` 的差异清单选择性补齐。
- **考勤**按课程安排在 v2 第 4 周变更涟漪中实现，届时同步更新规范与回归测试。
