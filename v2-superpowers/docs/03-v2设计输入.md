## 1. 范围（做什么）

| 编号 | 功能 | v2 必须达到的结果 |

| S2 | 采集飞书任务 | 任务创建与状态流转；字段含任务 ID、标题、负责人、参与人、状态、变更时间 |

### 3.1 功能验收

| 编号 | 标准 | 验证方式 |
|------|------|----------|

| F2 | 飞书任务字段完整率 100% | 抽查 20 条 |
| F3 | 群消息按发送人与时间归类，抽样 50 条准确率 ≥ 95% | 人工标注比对 |

| F5 | 团队日报覆盖全部有数据成员，格式统一；同一窗口重复生成结构一致 | 连续生成 2 次比对 |
| F6 | 凭证有效时邮件与飞书发送成功率 100%，失败有日志 | 发送测试日报并检查 |

| F9 | 考勤字段完整率 100%（状态、上班、下班、日期）；无记录输出「无考勤记录」 | 抽查 + 空数据用例 |
| F10 | 个人日报含「考勤」段；团队日报含考勤汇总 | 生成后逐段比对 |

### 3.2 性能与边界

| 编号 | 标准 |
|------|------|
| P1 | 10 人、3 仓库的采集 + 个人日报生成 ≤ 60 秒（不含限流等待） |
| P2 | 10 人团队日报汇总 ≤ 10 秒 |
| P3 | 日报列表/详情 API P95 < 500ms（本地 MySQL） |
| P4 | 连续 7 天运行，重复条目数为 0 |
| B1 | 成员当天无数据 → 输出「无产出」，不空白、不报错 |
| B2 | 请假/节假日 → 可标注，不计为异常 |
| B3 | 数据源失效 → 部分生成，明确标注缺失源，不整体崩溃 |
| B4 | 同一条记录重复采集 → 不重复计入 |
| B5 | 提交跨零点 → 按时间戳归入正确自然日 |
| B6 | 身份未映射 → 数据保留并标记「未归属」，绑定后可重新生成 |

## 4. 已验证的设计决策（ADR 结论）

> 以下为阶段一已论证并采纳的结论。v2 可以重新论证，但如果没有新的反例，默认沿用，避免重复踩坑。

| 编号 | 决策 | 核心理由 | 已知代价 |
|------|------|----------|----------|
| ADR-001 | HTTP 客户端用 `httpx` | 同步/异步一体，原生超时与连接池，`MockTransport` 便于测试 | 需自行封装重试与限流 |
| ADR-002 | 数据库用 MySQL 8（`aiomysql` + SQLAlchemy 2.x） | 本机已运行；并发写入；`utf8mb4` 中文友好 | 比 SQLite 多一层运维 |
| ADR-003 | 后端用 FastAPI | 原生 async，契合采集并发；Pydantic 校验；自动 OpenAPI | 需熟悉异步会话 |
| ADR-004 | 前端用 Vue 3 + Vite + Router + Pinia + Axios | 开发/构建快，组合式 API 适合中小页面 | 维护前后端两套工程 |
| ADR-005 | 日报生成用确定性规则模板 + 人工编辑留版本 | 同输入同输出，可测试、可追溯；不依赖外部模型 | 语言模板化 |
| ADR-006 | 定时调度用 APScheduler 进程内 | 与 FastAPI 同进程，部署简单 | 多实例会重复触发，v2 仍按单 worker 运行 |

## 5. 数据模型经验（表结构「教训」，不是建表 SQL）

v2 需要重新设计 schema，但以下约束已被 v1 验证有效，应保留：

### 5.1 核心实体（13 张）

| 表 | 作用 | 关键约束 |
|----|------|----------|
| `members` | 成员 | `email` 唯一；`role` ∈ member/leader/mentor；`status` ∈ active/inactive |
| `member_identities` | 外部身份绑定 | `(provider, external_id)` 唯一；`provider` ∈ github/feishu |
| `repositories` | 仓库配置 | `(owner, name)` 唯一；`enabled` 控制是否采集 |
| `raw_commits` | 原始提交 | **幂等键 `(repo_id, sha)`**；`committed_at` 索引；作者身份可空 |
| `raw_tasks` | 原始任务 | **幂等键 `task_id`**；负责人身份可空；参与人存 JSON |
| `raw_messages` | 原始消息 | **幂等键 `message_id`**；`(chat_id, sent_at)` 索引；只存截断摘要 + 哈希 |
| `identity_unmatched` | 未归属记录 | `(provider, external_id, source_type, source_id)` 唯一；可回填 `resolved_member_id` |
| `daily_reports` | 日报主表 | **唯一键 `(report_date, report_type, scope_key)`**；`scope_key` 个人为 `member:{id}`、团队为 `team` |
| `report_items` | 日报条目 | 记录 `source_type + source_id` 以支持追溯；`attribution_role` ∈ author/reviewer/assignee/participant/owner |
| `report_versions` | 编辑版本 | `(report_id, version)` 唯一；人工编辑必须留版本 |
| `push_logs` | 推送记录 | 每次尝试都写；`channel` ∈ email/feishu/console；`status` ∈ success/failed |
| `source_sync_state` | 增量同步状态 | `(source, resource_key)` 唯一；记录 cursor、status、error |
| `attendance_records` | 考勤日记录 | **唯一键 `(member_id, attendance_date)`**；状态 + 最早上班/最晚下班；原始打卡明细不落库 |
| `app_users` | 登录账号 | `username` 唯一；密码只存 PBKDF2 哈希；绑定 `member_id` 以支持成员视角 |

### 5.2 必须坚持的约束

- **原始表只读**：`raw_*` 只做 upsert，日报编辑不得修改原始数据；
- **幂等**：重复采集/重复生成不产生重复行，靠自然键 + 唯一索引兜底；
- **UTC 存储**：数据库统一存 UTC（naive），窗口按 Asia/Shanghai 计算后转 UTC，展示再转回；
- **日报唯一性**：团队日报的 `member_id` 为 NULL，唯一键必须带 `scope_key`，否则 NULL 会让唯一键失效；
- **考勤幂等**：`attendance_records(member_id, attendance_date)`，同日多次打卡在采集层聚合为一条；
- **版本留痕**：人工编辑写入 `report_versions`，`daily_reports.current_version` 指向当前版本；
- **索引**：按时间、作者/身份、日报日期、推送状态建索引，保证 P95 < 500ms。

## 6. 接口契约（v2 可沿用同名概念，实现重写）

### 6.1 通用类型

```python
@dataclass(frozen=True)
class TimeWindow:
    start: datetime  # 含
    end: datetime    # 不含
    tz: str = "Asia/Shanghai"

@dataclass
class SourceError:
    source: str
    code: str          # AUTH / RATE_LIMIT / NETWORK / PARSE
    message: str
    retryable: bool

@dataclass
class CollectionResult(Generic[T]):
    items: list[T]
    partial: bool = False
    errors: list[SourceError] = field(default_factory=list)
    cursor: str | None = None
```

约定：
- 时间窗口半开区间 `[start, end)`；
- 只有凭证完全缺失才抛 `AuthError`；单数据源失败返回 `partial=True + errors`，不中断整份日报；
- 所有写入使用自然键 upsert。

### 6.2 采集层

```python
class Collector(Protocol[T]):
    source: str
    async def collect(self, window: TimeWindow) -> CollectionResult[T]: ...
```

| 采集器 | 关键行为 |
|--------|----------|
| `GitHubCollector` | 按仓库分页（100/页）；403/429 指数退避最多 3 次；超时 15s；按 `(repo_id, sha)` 去重 |
| `FeishuTaskCollector` | 先取 tenant_access_token，过期刷新；按 `task_id` upsert；限流返回 partial |
| `FeishuMessageCollector` | 仅采集配置的 `chat_id`；按 `message_id` 去重；内容截断 500 字并脱敏 |
| `FeishuAttendanceCollector` | 按成员+日期聚合考勤；限流/权限失败返回 partial；未映射身份写 `identity_unmatched` |
| `MockCollector` | 无凭证时生成当天提交/任务/消息/考勤，供演示与测试 |

### 6.3 生成层

```python
class IdentityResolver:
    async def resolve(self, provider, external_id, external_username, email) -> int | None: ...

class AttributionEngine:
    def attribute(self, records: list[RawRecord]) -> list[AttributedItem]: ...

class PersonalReportGenerator:
    def generate(self, member, report_date, items,
                 attendance: AttendanceRecord | None = None) -> GeneratedReport: ...

class TeamReportGenerator:
    def generate(self, report_date, personal_reports,
                 attendance_by_member: dict[int, AttendanceRecord] | None = None) -> GeneratedReport: ...
```

归属规则：commit 作者 → `author`；PR reviewer → `reviewer`；任务负责人 → `owner`；任务参与人/群消息发送人 → `participant`；按 `(source_type, source_id, member_id, role)` 去重，不做比例拆分。

### 6.4 推送层与编排

```python
class Pusher(Protocol):
    channel: str
    async def push(self, report, target: str) -> PushResult: ...

class DailyReportOrchestrator:
    async def run(self, report_date: date, push: bool = True) -> RunSummary: ...
```

编排顺序：运行锁 → 加载成员/仓库 → 并行采集 → 规范化 upsert → 身份解析 → 归属去重 → 个人日报 → 团队日报 → 持久化 → 推送 → 更新同步状态。

### 6.5 HTTP API（最小集合）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查，只返回凭证是否就绪 |
| POST | `/api/auth/login` | 登录，返回 JWT |
| GET | `/api/auth/me` | 当前用户 |
| GET | `/api/reports` | 日报列表；member 只能看团队 + 本人 |
| GET | `/api/reports/{id}` | 日报详情 |
| PUT | `/api/reports/{id}` | 编辑并生成新版本 |
| POST | `/api/reports/generate` | 手动生成 |
| POST | `/api/reports/{id}/push` | 手动推送 |
| GET | `/api/members` | 成员列表 |
| POST | `/api/members/{id}/identities` | 绑定身份 |
| GET | `/api/identities/unmatched` | 未归属记录 |
| GET | `/api/sources/status` | 数据源同步状态 |
| GET | `/api/push-logs` | 推送记录 |
| GET | `/api/attendance?date=` | 查询考勤；member 只能看本人 |

统一错误码：`400 VALIDATION_ERROR`、`401 UNAUTHORIZED`、`403 FORBIDDEN`、`404 NOT_FOUND`、`409 CONFLICT`、`502 SOURCE_UNAVAILABLE`、`500 INTERNAL_ERROR`。

## 7. 非功能性约束

- **限流**：GitHub 1 请求/秒令牌桶，403/429 指数退避（1s/2s/4s + 抖动）最多 3 次；飞书 5 请求/秒；
- **密钥**：只从 `.env` 读取；代码/日志/错误信息不得出现明文；日志对 token 掩码；健康检查只返回布尔值；
- **重试**：只对幂等 GET 重试；写操作不自动重试；采集超时 15s，推送超时 30s；
- **降级**：单源失败 `partial=True`，团队日报标注缺失；
- **安全**：ORM 参数化，禁止拼接 SQL；Pydantic 校验入参；CORS 只允许本地前端；群消息只存摘要与哈希；权限三级；
- **性能**：见 P1–P4；
- **可维护**：全量类型注解，`ruff` 清零，关键路径单元测试 + 集成测试。

## 8. v2 的差异化决定

| 决定 | 说明 |
|------|------|
| 独立数据库 | 使用 `daily_report_v2`，不碰 v1 的 `daily_report` |
| 重新设计 schema | 表名/字段可沿用概念，但建表 SQL 由 v2 重新编写并评审，不复制 v1 的 `schema.sql` |
| 重新实现业务代码 | 采集、生成、推送、编排、API、前端全部新写；允许概念相同，不允许文件复制 |

| 先核心后扩展 | 先完成 S1–S9 的核心链路，再做 v1 中额外的管理工作台；差异记录在 `V2-064` |
